# Запуск аккаунтов: чек-лист владельца

Код аккаунтов и облачных проектов готов и скрыт за флагами
(`docs/accounts-and-projects-plan.md`). Этот список — то, что нужно сделать вне
кода, по порядку. Технические подробности — в [`DEPLOY.md`](../DEPLOY.md), здесь
ссылки на его разделы. Пункты помечены: **вы** — делаете сами, **мне** — что
передать в чат, чтобы я внёс в код.

Главное правило 152-ФЗ, которое определяет выбор подрядчиков: персональные данные
(почта, имя, проекты) должны собираться и храниться в базах на территории РФ, а
их передача сервисам за рубежом — отдельная трансграничная передача со своим
уведомлением в Роскомнадзор. Проще всего выбирать российских провайдеров везде,
куда попадают адреса или содержимое аккаунтов.

## 1. Сервер в РФ

- [ ] **вы** Арендовать VPS у российского провайдера (Selectel, Yandex Cloud,
      Timeweb Cloud, VK Cloud и т. п.), дата-центр в России. Для старта хватит
      2 vCPU / 4 ГБ RAM / 40 ГБ SSD, Ubuntu 24.04 LTS.
- [ ] **вы** Сменить все доступы, которые когда-либо были раскрыты, создать
      отдельного deploy-пользователя, вход только по личным SSH-ключам, root и
      пароли по SSH выключить, настроить firewall (`DEPLOY.md`, §7).
- [ ] **вы** Заполнить `.env.server` по `.env.server.example`: длинные разные
      пароли для трёх ролей БД, аккаунты пока выключены
      (`AUTH_ENABLED=false`, `NEXT_PUBLIC_AUTH_ENABLED=false`) (`DEPLOY.md`, §1).
- **мне** Название провайдера и город — они попадут в политику
  конфиденциальности (поле `hosting`).

## 2. Домен и HTTPS

- [ ] **вы** A-запись домена на IP сервера; `SITE_ADDRESS` и
      `PUBLIC_ORIGIN=https://<домен>` в `.env.server` (`DEPLOY.md`, §2).
- [ ] **вы** Первый запуск (`DEPLOY.md`, §3) и проверка:
      `curl -I https://<домен>` — ответ 200, есть `Strict-Transport-Security`;
      `https://<домен>/api/health/ready` — `{"status":"ok"}`.

## 3. Резервные копии с проверкой восстановления

- [ ] **вы** Внешнее хранилище в РФ (Yandex Object Storage, Selectel S3 и т. п.)
      с отдельным ключом доступа только на запись в один bucket.
- [ ] **вы** Ежедневный зашифрованный `pg_dump`: ключ `age` создать у себя,
      на сервер поставить `infra/backup` и таймер, в bucket задать
      lifecycle-правила 7 / 4 / 6 (`DEPLOY.md`, §5.1–5.2).
- [ ] **вы** Первое восстановление на отдельной машине до включения аккаунтов,
      дальше — раз в месяц: `infra/backup/restore-drill.sh`
      (`DEPLOY.md`, §5.3). Записывать дату и результат.
- **мне** Срок хранения копий — поле `backupRetention` в политике.

## 4. Мониторинг

- [ ] **вы** Внешний uptime-сервис на три адреса: `/`, `/api/health/live`,
      `/api/health/ready`, плюс предупреждение об истечении TLS-сертификата
      (`DEPLOY.md`, §8). Uptime-проверки не передают персональные данные, их
      можно брать любые.
- [ ] **вы** Оповещения о диске (>80 %) и памяти на сервере; контроль, что
      последний off-site backup не старше суток: три проверки Healthchecks.io
      из `DEPLOY.md`, §5.1 и §8.
- [ ] **вы** Сбор ошибок: либо self-hosted (GlitchTip / Sentry на своём сервере
      в РФ), либо только логи Docker. Облачный Sentry за рубежом — это
      трансграничная передача, без отдельного уведомления не подключать.

## 5. Почта (SMTP)

- [ ] **вы** Выбрать российский сервис транзакционных писем (Yandex Cloud
      Postbox, Unisender Go и т. п.). Зарубежные (Mailgun, SendGrid) получают
      адреса пользователей — это трансграничная передача.
- [ ] **вы** Подтвердить у провайдера домен отправителя и добавить в DNS записи,
      которые он выдаст: SPF (`TXT v=spf1 …`), DKIM (`TXT` или `CNAME`), DMARC
      (`TXT _dmarc … v=DMARC1; p=none; rua=mailto:…` на старте, позже
      `p=quarantine`).
- [ ] **вы** Заполнить в `.env.server`: `SMTP_HOST`, `SMTP_PORT` (587 со
      STARTTLS или 465 с `SMTP_SECURE=true`), `SMTP_USER`, `SMTP_PASSWORD`,
      `SMTP_FROM="StyleFinder <contact@stylefinder.online>"` (`DEPLOY.md`, §1).
- [ ] **вы** После включения (шаг 8) отправить письмо сброса пароля на ящики
      Яндекс, Mail.ru и Gmail. Письмо во «Входящих», в заголовках
      `spf=pass`, `dkim=pass`, `dmarc=pass`.
- **мне** Название почтового сервиса — поле `mailProvider` в политике.

## 6. Юридическая часть (152-ФЗ)

- [ ] **мне** Реквизиты оператора: ФИО ИП или название организации, ИНН и
      ОГРН/ОГРНИП, почтовый адрес для обращений, e-mail для обращений по
      персональным данным. Я заполню `next/src/shared/legal/operator.ts`; пока
      там есть заглушки, `/privacy` и `/consent` показывают плашку «Черновик».
- [ ] **вы** Отдать юристу тексты `/privacy` и `/consent` (после заполнения
      реквизитов). Если юрист меняет текст согласия — **мне**: новый текст,
      я обновлю страницы и подниму версию согласия в API и на сайте.
- [ ] **вы** Подать в Роскомнадзор уведомление об обработке персональных данных
      (портал pd.rkn.gov.ru или Госуслуги) до начала сбора данных. Если где-то
      остаётся зарубежный сервис с данными пользователей — отдельное
      уведомление о трансграничной передаче.
- [ ] **вы** Назначить ответственного за обработку персональных данных и
      сохранить внутренний документ о мерах защиты (юрист подскажет форму).

## 7. Старые аккаунты

- [ ] **вы** Если в базе уже есть пользователи (дизайнеры), предупредить их:
      после включения войти по старому паролю не получится, нужен «Забыли
      пароль?» → письмо → новый пароль (`DEPLOY.md`, §8). Их аккаунты фоновая
      очистка не удаляет.

## 8. Включение

- [ ] **вы** Свежий backup перед включением.
- [ ] **вы** На последнем commit прогнать локально
      `cd next && npm run test:e2e:accounts` (нужен Docker).
- [ ] **вы** Сначала только вход, без регистрации:
      `AUTH_ENABLED=true`, `AUTH_REGISTRATION_ENABLED=false`,
      `NEXT_PUBLIC_AUTH_ENABLED=true`, `NEXT_PUBLIC_AUTH_REGISTRATION_ENABLED=false`,
      пересобрать `next` и перезапустить `nest` (`DEPLOY.md`, §4). Проверить
      вход своим аккаунтом, сброс пароля, сохранение проекта, «Мои проекты»,
      выход.
- [ ] **вы** Затем регистрация: оба `…REGISTRATION_ENABLED=true`, пересборка.
      Проверить регистрацию на новый ящик, письмо подтверждения, перенос
      гостевого черновика.
- [ ] **вы** Первые дни смотреть логи API по событиям `account.*` и
      `account.maintenance` (раз в 6 часов: сколько сессий и аккаунтов удалено).
