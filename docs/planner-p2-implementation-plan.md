# P2: ортогональные комнаты и сегментная геометрия

## Цель

Добавить безопасную поддержку Г-образных комнат без регрессий для существующих прямоугольных проектов. Контур должен одинаково пониматься моделью, валидатором, решателем, редактором, черновиком, экспортом и Room Lab. Нельзя показывать ортогональный контур, пока мебель и служебные зоны продолжают проверяться только по bounding box.

## Контракт модели

`Room.width` и `Room.depth` остаются размерами bounding box для обратной совместимости. Новое поле `geometry` версионирует форму:

```ts
type RoomGeometry =
  | { version: 1; kind: "rect" }
  | { version: 1; kind: "orthogonal"; vertices: RoomVertex[] };
```

- отсутствие `geometry` означает legacy-прямоугольник;
- прямоугольник получает стабильные сегменты `rect-top`, `rect-right`, `rect-bottom`, `rect-left`;
- ортогональный контур хранит вершины в порядке обхода, без повторения первой вершины;
- стабильный id сегмента выводится из id его начальной вершины;
- дверь, окно и радиатор сохраняют legacy `wall`, но для ортогонального контура обязаны иметь `segmentId`;
- `offset` измеряется от начала выбранного сегмента;
- `width/depth` всегда совпадают с габаритами контура.

## Инварианты контура

- только горизонтальные и вертикальные рёбра;
- не менее 6 вершин для непрямоугольной формы;
- шаг координат 50 мм;
- длина каждого сегмента не менее 500 мм;
- нет нулевых рёбер, повторяющихся соседних вершин, самопересечений и касаний несоседних рёбер;
- контур имеет положительную площадь и нормализованный обход;
- проём полностью помещается на своём сегменте;
- тело мебели и каждая обязательная зона целиком лежат внутри контура, включая проверку вогнутого выреза;
- служебные зоны двери, окна и радиатора не могут тихо обрезаться контуром.

## Этапы реализации

### P2a — геометрическое ядро

1. Добавить versioned `RoomGeometry`, вершины, сегменты и `segmentId` у объектов стены.
2. Создать `room-geometry.ts` как единый адаптер:
   - canonical geometry и boundary segments;
   - bounds, area, centroid;
   - строгая валидация ортогонального polygon;
   - point/rect containment с учётом вогнутых углов;
   - преобразование segment offset в мировые координаты;
   - inward normal, проекция и wall contact.
3. Покрыть legacy rectangle и L-контур unit-тестами.

### P2b — hard rules и solver

1. Перевести body/clearance containment на новый адаптер.
2. Перевести дверь, окно и радиатор на segment-based obstacle geometry.
3. Проверять bounds и пересечения проёмов по сегментам.
4. Генерировать wall-contact candidates вдоль всех boundary segments.
5. Оставить bounding grid как детерминированный источник кандидатов, но отбрасывать всё вне polygon.
6. Использовать площадь/центр контура в ranking.
7. Адаптировать proof прохода 700 мм к polygon cells; ложный `success` запрещён.

### P2c — сохранение и экспорт

1. Поднять local draft до v4, читать v4 → v3 → v2 → v1.
2. Мигрировать legacy стены в стабильные rect segment ids; повторно валидировать layout.
3. Включить geometry и segment anchors в stale signature и observation snapshot.
4. Поднять plan spec до v3 и algorithm до v4.
5. PNG рисует polygon path и segment openings; bounding rectangle не используется как контур.

### P2d — редактор

1. Заменить boolean редактирования на режимы furniture / openings / boundary.
2. Добавить безопасные пресеты: прямоугольник, Г-образная слева, Г-образная справа.
3. Рисовать boundary в SVG; мебель остаётся HTML-слоем внутри общих координат.
4. Дать мышь, touch и клавиатуру для вершин/сегментов; шаг 50 мм, touch target 44 px.
5. Gesture хранит initial snapshot; Escape/pointercancel откатывают целиком.
6. Изменение контура делает результат stale и не запускает solver во время gesture.
7. Проёмы остаются на segment id и clamp-ятся при изменении длины.

### P2e — качество и выпуск

1. Сохранить зелёными все существующие rectangular unit/golden/Room Lab cases.
2. Добавить L-room fixtures: валидная расстановка, вырез, узкий перешеек, внутренний сегмент, невозможный проход.
3. Добавить draft/export/signature regression tests.
4. Playwright desktop + mobile: preset, vertex keyboard/drag, opening anchor, Escape, reload, stale result.
5. Build, typecheck, lint, `git diff --check`, targeted и полный planner regression suite.

## Acceptance criteria

- Старый v3 rectangular draft восстанавливается без потери анкеты, комнаты, мебели и валидной расстановки.
- Две формы с одинаковыми `width/depth`, но разными контурами имеют разные signatures.
- Ни body, ни hard/one-of clearance не могут попасть в вырез Г-комнаты.
- Проёмы корректно работают на внешних и внутренних сегментах.
- 700-мм proof не прокладывает путь через пустой вырез или слишком узкий перешеек.
- Solver детерминирован и не возвращает `success` для невалидной polygon-расстановки.
- Экран, сохранённый draft и PNG показывают один и тот же контур.
- Прямоугольный пользовательский поток не меняется без явного выбора новой формы.

## Граница релиза

Ортогональный режим включён после прохождения geometry, solver, draft, export и desktop/mobile e2e. Доступны проверенные Г-пресеты и общий draw-mode на том же валидаторе. У Г-пресетов есть прямая ручка внутреннего угла; произвольный применённый контур пока изменяется безопасным повторным рисованием.
